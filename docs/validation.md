# Проверка версии 0.2.0

В Linux-среде разработки выполнены:

- CMake Release-сборка переносимой логики с предупреждениями как ошибками; CTest: 2/2 набора прошли, 44 проверки политик и 75 проверок новых функций.
- Кросс-сборка Windows x64 через GCC / MinGW-w64 14 с `-Wall -Wextra -Wpedantic -Werror`: CrimeSQLRecovery.exe, CrimeSQLObserver.exe и тесты собраны.
- Windows-интеграционные тесты под Wine 10: **43 проверки прошли**. Это реальные операции с отдельным временным ключом HKCU и безвредными файлами: восстановление значения, точная резервная копия UTF-16, отказ при устаревшем наблюдении, создание/удаление/переименование через ReadDirectoryChangesW, сохранение конфигурации Sandbox без перезаписи существующего файла, приоритет своего процесса с возвратом исходного. Реальные политики и автозапуск тест не меняет.
- Исправлен разбор плотно упакованных уведомлений: он использует memcpy и проверку границ, не требует выравнивания каждой записи по DWORD. Добавлен тест на этот случай и некорректные длины.
- Приложение запущено под Wine: проверены навигация, диагностика, отрисовка, игра с открытием карточек, ввод/сохранение Ctrl+Shift+K для мыши, загрузка настройки после перезапуска. Затем окно свёрнуто через ShowWindow(SW_MINIMIZE): глобальное сочетание вызвало действие и показало результат сброса области курсора.
- Наблюдатель запущен отдельно под Wine и показал реальные тестовые файловые события. На снимке observer-wine.png — безвредные события тестов, не запуск вируса и не сеанс настоящей Windows Sandbox.
- Таблицы импортов обоих MinGW EXE содержат DLL Windows, без отдельных DLL GCC / libstdc++.

## Что эти проверки не подтверждают

Wine не является Windows Sandbox. Полный цикл запуска Sandbox, вложенная виртуализация, запуск установщиков и работа с заражённой системой здесь не проверялись. Команда Microsoft Defender не запускалась: в среде нет Defender. Поведение BlockInput в Wine — заглушка, поэтому снятие реальной блокировки ввода не подтверждено. В приложении явно указаны ограничения Windows на чужие блокировки.

GitHub Actions выполняет сборку MSVC x64 и все три набора тестов на windows-latest; выпуск с ZIP создаётся только после успешных заданий Windows и Linux. Наличие workflow само по себе не подтверждает результат конкретного запуска.

## Проверка на тестовой Windows перед использованием с образцами

Используйте одноразовую тестовую VM Windows Pro/Enterprise/Education с виртуализацией и включённой Sandbox. Начните с безвредного EXE, который создаёт, меняет, переименовывает и удаляет файлы. Убедитесь, что наблюдатель готов до старта образца, показывает старое и новое имя, а основной ПК не изменяется. Проверьте отсутствие сети, общего буфера обмена и записи в папку образца; при закрытии Sandbox журнал должен удаляться.

Отдельно проверьте автозапуск после входа и отключение через интерфейс, реальную фильтрацию клавиш с восстановлением прежних настроек доступности, бинды при свёрнутом окне, DPI на используемых мониторах, команду Defender и обратный импорт .reg. Включение этих функций в UI не заменяет проверку на конкретной версии Windows.
