# CrimeSQL dev system recovery · 0.3.1

Утилита восстановления Windows 10/11 x64 на C++17 / Win32 / GDI+. Исправленная буферизованная отрисовка, горячие клавиши, средства восстановления Windows, изолированная лаборатория EXE и шесть мини-игр.

## Скачать и запустить

В [последнем выпуске](https://github.com/Bezsmertny/SU---Added-by-Crimesql/releases/latest) скачайте **CrimeSQL-dev-system-recovery-Windows-x64.zip** из Assets. Распакуйте **всю папку** и запустите **CrimeSQLRecovery.exe**. Второй файл, `CrimeSQLObserver.exe`, нужен лаборатории — оставьте его рядом.

Обычный запуск не требует прав администратора и не изменяет политики. Публикация среды Codex не отправляет исходники в GitHub: для этого используются Git commit/push. Для выпуска настроен GitHub Actions на тегах `v*`.

## Восстановление и защита

- Проверка четырёх ограничений **текущего пользователя HKCU**: диспетчер задач, редактор реестра, командная строка, панель управления. Восстановление выбранного распознанного значения выполняется после подтверждения, с исходным значением в UTF-16 `.reg` и повторной проверкой результата.
- **Мышь:** сброс ограничения области движения `ClipCursor`, запрос освобождения собственной блокировки `BlockInput`.
- **Клавиатура:** отключение включённой фильтрации клавиш на текущий сеанс после подтверждения, запрос освобождения собственной блокировки ввода.
- **Microsoft Defender:** запуск настоящей полной проверки `Start-MpScan -ScanType FullScan` с запросом повышения прав. Она может занять долгое время; результаты обнаружений смотрите в «Безопасности Windows». Успешное завершение команды не означает отсутствие угроз.
- Открытие штатных средств защиты, восстановления и диагностики. Локальный журнал действий с копированием.

**Границы восстановления ввода:** Windows не разрешает обычному процессу снять `BlockInput`, удерживаемый чужим потоком. Приложение не удаляет чужие перехватчики и драйверы. При полной блокировке горячая клавиша может не поступить приложению; нажмите **Ctrl+Alt+Del**. Кнопки сообщают о конкретно выполненной операции и не заявляют, что любая блокировка снята.

Ограничение политики само по себе не доказывает заражение. Приложение не является антивирусом; удалением угроз занимается установленное средство защиты. На рабочем или учебном ПК согласуйте изменение политик с администратором.

## Бинды, автозапуск, приоритет

В разделе **«Настройки и бинды»** нажмите нужное сочетание в поле и выберите **«Сохранить и применить бинды»**. Используйте Ctrl или Alt с буквой, цифрой либо F1–F24. Если сочетание занято, приложение сообщает об этом и пытается восстановить старые назначения.

| Действие | По умолчанию |
|---|---|
| Освободить мышь | Ctrl+Alt+F8 |
| Восстановить клавиатуру | Ctrl+Alt+F9 |
| Восстановить / открыть диспетчер задач | Ctrl+Alt+F10 |

Бинды глобальные и работают, пока CrimeSQL запущен, в том числе свёрнутым. Для изменения политик и настроек доступности сохраняются подтверждения.

Автозапуск включается вручную через HKCU Run только для текущего пользователя, без службы, задания планировщика или скрытой установки. Он запускает приложение свёрнутым (`--background`). Не перемещайте распакованную папку после включения; выключение доступно той же кнопкой.

Высокий приоритет применяется **только к процессу CrimeSQL**, не к образцам и не ко всей системе. Режим реального времени не используется. Это настройка планировщика, а не способ защиты от вирусов. По умолчанию приоритет обычный, автозапуск выключен. Анимации можно отключить.

## Лаборатория EXE

Нужны **Windows 10/11 Pro, Enterprise или Education**, включённая виртуализация и компонент **«Песочница Windows»**. Доступность компонента определяется перед запуском; наличие файла WindowsSandbox.exe ещё не гарантирует, что виртуализация работает. На Windows Home эта функция не поддерживается. См. [конфигурацию Windows Sandbox](https://learn.microsoft.com/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file).

1. Откройте «Лаборатория EXE» и выберите файл.
2. После подтверждения приложение копирует только образец и наблюдатель в отдельную папку сеанса и считает SHA-256 копии.
3. Windows Sandbox запускается **без сети, общего буфера обмена, принтеров, микрофона, камеры и vGPU**. Единственная папка основного ПК подключена **только для чтения**. Папки пользователя, весь диск и каталог приложения не передаются.
4. Внутри Sandbox наблюдатель сначала начинает читать изменения `C:\`, затем создаёт маркер готовности. Только после этого команда Sandbox запускает копию образца **внутри виртуальной среды**. Если наблюдатель не готов за 30 секунд, образец не запускается. На основном ПК приложение образец не запускает.
5. В окне **CrimeSQLObserver** появляются время, действие, путь и новое имя. Поддерживаются создание, изменение, удаление и переименование файлов и папок, включая изменения в `Windows\System32` внутри Sandbox. Список ограничен последними 10 000 событиями; переполнение очереди/буфера явно отмечается как потеря событий.

Это **наблюдение файловой системы всей Sandbox**, а не доказательство авторства конкретного EXE. Фоновые события Windows тоже попадают в журнал. Изменения реестра, сетевые обращения, содержимое файлов и действия до запуска наблюдателя не отслеживаются. Не все вредоносные программы проявляют себя в Sandbox; некоторые требуют сети, перезапуска или дополнительных файлов, либо могут остановить наблюдатель. Изоляция не является абсолютной гарантией безопасности.

Журнал виден **внутри Sandbox**. Кнопка сохранения создаёт TSV тоже внутри неё; при закрытии среды журнал удаляется. Автоматической записи отчётов в основной ПК нет. Папки `LabSessions` с копиями образцов остаются на основном ПК: удаляйте ненужные сеансы вручную после закрытия Sandbox, не запускайте сохранённые образцы.

## Средства восстановления

Раздел «Инструменты» содержит пять вкладок:

| Вкладка | Возможности |
|---|---|
| Защита | Безопасность Windows, быстрая/полная проверка Defender, автономная проверка Defender |
| Система | SFC `/verifyonly`, SFC `/scannow`, DISM `/Online /Cleanup-Image /RestoreHealth`, точки восстановления |
| Консоли / WinRE | PowerShell администратора без профиля, CMD администратора без AutoRun, `reagentc /info`, параметры восстановления |
| Отчёты | Аудит Run/RunOnce, настройки автозагрузки, сведения о системе, экспорт диагностики |
| Шрифты | Восстановление настроек Segoe UI с копией `.reg`, параметры шрифтов Windows |

**PowerShell администратора работает в текущей Windows. Это не отдельный «режим восстановления».** Для настоящего WinRE откройте «WinRE и безопасный режим», сохраните работу и выберите расширенный запуск в настройках Windows. В штатной WinRE обычно доступна командная строка CMD; PowerShell по умолчанию там не установлен.

SFC и DISM восстанавливают повреждения Windows, а не удаляют вредоносные программы. Изменяющие систему команды требуют подтверждения; затем Windows запрашивает права администратора. DISM может использовать Windows Update и сеть. Вывод команд остаётся в окне PowerShell; нажмите Enter после просмотра, чтобы закрыть его. Журналы сохраняются в `Reports`. Сам факт успешного запуска или код 0 не подтверждают отсутствие угроз.

**Автономная проверка Defender перезагружает компьютер.** Она требует отдельного подтверждения, сохранённой работы и настроенного WinRE. При включённом BitLocker подготовьте ключ восстановления. Никаких автоматических перезагрузок при запуске приложения или диагностике нет.

Аудит автозагрузки читает Run/RunOnce в HKCU/HKLM, включая 32-битное представление HKLM, и открывает локальный текстовый отчёт. Он ничего не удаляет и не охватывает службы, задачи планировщика и все способы закрепления. Проверьте личные пути и аргументы команд перед отправкой отчёта кому-либо.

## Вернуть читаемые системные шрифты

Откройте **Инструменты → Шрифты → Вернуть системные шрифты**, подтвердите изменение и запрос администратора Windows. Операция исправляет настройки стандартного семейства Segoe UI:

- восстанавливает его регистрации в 64-битном `HKLM\Software\Microsoft\Windows NT\CurrentVersion\Fonts`;
- удаляет подмены выбранных начертаний в `FontSubstitutes` HKLM и исходного пользователя, а также его регистрации, перекрывающие эти системные шрифты;
- возвращает Segoe UI 9 pt для шести значений WindowMetrics: заголовков, малых заголовков, меню, статуса, сообщений и подписей значков;
- на Windows 11 также обрабатывает Segoe UI Variable, если его файл присутствует. Отсутствующие необязательные начертания не регистрируются.

Перед первой записью создаётся уникальная UTF-16 копия `Backups\Fonts-{GUID}.reg`, включая типы и данные исходных значений и удаление новых значений при откате. Запись и результат перепроверяются; при ошибке приложение пытается отменить свои изменения, не затирая обнаруженные параллельные правки. Ошибка копирования, чтения или отсутствие одного из четырёх основных файлов Segoe UI прерывает операцию до изменений. Некорректные строки, которые Windows нормализует при импорте `.reg`, отклоняются, поскольку точный откат для них не гарантирован.

**После успеха сохраните работу, выйдите из учётной записи Windows и войдите снова.** Приложение не завершает сеанс автоматически. Пользовательские размеры шрифта этих элементов заменяются стандартными 9 pt с учётом системного DPI; остальные установленные шрифты, размеры окон, масштаб экрана и кэш шрифтов не очищаются.

Если UAC выполняется под другой учётной записью администратора, реестр исходного пользователя выбирается по SID, а копия сохраняется в `Backups` той учётной записи, под которой выполняется повышенная операция. Точный полный путь показан в её результате. Для ручного отката проверьте `.reg` и импортируйте его с правами администратора, когда исходный пользователь вошёл в систему: записи `HKEY_USERS` содержат его SID.

Это восстановление **настроек**, а не файлов шрифтов или удаление угроз. Наличие непустого файла не подтверждает его целостность. Если файлы удалены или повреждены, используйте **Инструменты → Система → проверка SFC**, затем при необходимости восстановление SFC/DISM. Шрифты не скачиваются с посторонних сайтов; неизвестные подмены других семейств не удаляются.

## Настройки, копии и мини-игры

Данные расположены в `%LOCALAPPDATA%\CrimeSQL dev system recovery`:

- `settings.ini` — бинды, приоритет, анимации;
- `Backups` — исходные значения политик в `.reg`;
- `LabSessions` — копии выбранных образцов и конфигурации `.wsb`;
- `Reports` — журналы операций и отчёты диагностики/автозагрузки.

Если резервную копию записать не удалось, политика не изменяется. Для отката проверьте нужный `.reg` и импортируйте его **в той же учётной записи**: это вернёт исходное ограничение. Старые копии версии 0.1.0 остаются в `%LOCALAPPDATA%\NEDOHACKERS lite\Backups`.

В разделе «Перерыв» теперь шесть игр: пары, реакция, крестики-нолики против компьютера, пятнашки, «Саймон» и Lights Out. Пятнашки и Lights Out генерируются с решением. «Саймон» показывает последовательность, которую нужно повторить; кнопка «Новая игра» сбрасывает текущую игру. Мини-игры не изменяют систему и не влияют на защиту.

Отрисовка кнопок полностью буферизована, включая нажатия, фокус и печать. Страницы меняют только нужные позиции/видимость; все кнопки больше не скрываются и не показываются заново. Буферы повторно используются. На статических страницах в простое анимационный таймер выключен; при свёрнутом/неактивном окне декоративная анимация не крутится.

## Сборка

Visual Studio 2022 / Build Tools: **Desktop development with C++**, Windows SDK, CMake 3.20+. Сторонние GUI-библиотеки не нужны; MSVC runtime включается статически.

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure
.\build\Release\CrimeSQLRecovery.exe
```

Linux проверяет переносимую логику, не GUI Windows:

```sh
cmake -S . -B build
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

`recovery_tests` проверяет политики и `.reg`. `feature_tests` — бинды, изоляцию конфигурации Sandbox, переименования и пары. `game_tests` — новые игры и команды восстановления. `windows_integration_tests` использует отдельный временный ключ HKCU и безвредную временную папку: проверяет резервные копии, отказы при устаревшем значении и реальные создание/переименование/удаление файлов через ReadDirectoryChangesW. Автозапуск, настройки доступности и реальные системные политики тест не меняет. `ui_tests` запускает отдельный процесс `--ui-test` и проверяет цвета кнопок, нажатия, 84 цикла навигации/размера, сворачивание, GDI-ресурсы и отсутствие таймера на статической странице. Отдельный Windows smoke-тест проверяет запуск PowerShell/CMD, справку SFC/DISM и сведения WinRE без исправлений и перезагрузки. Итоги и оставшиеся ручные проверки — [docs/validation.md](docs/validation.md).

`font_recovery_tests` проверяет реальные записи и откат только во временных ключах реестра, включая импорт `.reg` через reg.exe и отказ в записи по DACL. Настоящие настройки системных шрифтов в тестах не меняются.
